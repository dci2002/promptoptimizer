# 1. Стэк технологий
- **Python 3.10+** (`list[str]` annotations)
- **langchain-core** — `@tool` decorators, messages
- **langchain-openai** — `ChatOpenAI` against any OpenAI-compatible endpoint
  (`api_base` is configurable; in the shipped config both LLMs point at
  local vLLM-style servers: qwen for llm1, gemma for llm2)
- **langgraph** — `create_react_agent` ReAct runtime
- **PyYAML** — configuration
- `reasoning_effort=None` is explicitly set on every LLM call to disable
  extended-thinking modes on the local servers
- **pywebview**-пользовательский интерфейс на стороне python, vanila javascript - для действий на веб-странице
- **ключевой дизайн-шаблон исполнения** - реализация кода в файле `/scripts/template/interview_copilot.py`
- **архитектурный дизайн** - в файле `/scripts/template/design.md`

# 2. Интерфейс
## Две закладки:
### 2.1. "Промпты"
- 2.1.1. **Область настроек промпта** - содержит поля: "**Промпт**" (для многострочного поля высотой 10 строк), "**Результат**" (с **кнопкой "Выполнить промпт**"), **таблица переменных** (с кнопками "Добавить", "Удалить") с колонками: Переменная, Значение
- 2.1.2. **Область исполнения** - содержит **кнопку "Старт"**, **поле "Прогресс"** для отслеживания прогресса (многострочное, высотой 10 строк), **поле "Результат оптимизации"** - многострочное поле (высотой 10 строк)
- 2.1.3. **Область "Human-in-the-loop"** - содержит **флаг "Human-in-the-loop"** и два многострочных поля (высота 10 строк): **"Промпт-источник"** (рядом с полем **кнопка "Копировать"** - в буфер обмена), **"Промпт-результат"** (доступны если включен флаг, иначе очищаются и недоступны)
### 2.2. "Настройки"
- 2.2.1. **Таблица "Список LLM"** с кнопками "Добавить", "Редактировать", "Удалить", колонки: name, api_base, api_key, model, temperature
- 2.2.2. Два поля **LLM as Judge**, **LLM for prompts** - выпадающий список имен LLM из таблицы 2.2.1

# 3. Сценарии пользователя
- **3.1. Добавить настройки новой LLM**
  - Пользователь нажимает на кнопку "Добавить" 
  - в открывшемся окне задает настройки name (текстовое), api_base (текстовое), api_key (текстовое), model (текстовое), temperature (числовое, дробное) - все поля обязательны для сохранения
  - нажимает кнопку "Сохранить" (или "Отмена" если сохранять не нужно) - если сохранить - данные сохраняются в файле config.yaml
- **3.2. Редактировать настройки LLM**
  - пользователь выбирает в таблице 2.2.1 строку с настройками для редактирования, двойным щелчком или по кнопке "Редактировать" открывает окно редактирования настроек
  - в открывшемся окне задает настройки name (текстовое), api_base (текстовое), api_key (текстовое), model (текстовое), temperature (числовое, дробное) - все поля обязательны для сохранения
  - нажимает кнопку "Сохранить" (или "Отмена" если сохранять не нужно) - если сохранить - данные сохраняются в файле config.yaml
- **3.3. Удалить настройку LLM**
  - пользователь выбирает в таблице 2.2.1 строку с настройками для удаления
  - нажимает кнопку "Удалить" - после подтверждения строка удаляется из списка - из config.yaml удаляется соответствующая настройка
- **3.4. Выбрать настройки LLM as Judge, LLM for prompts** 
  - в выпадающем списке имен LLM из таблицы настроек 2.2.1 выбирается требуемая
  - после выбора выбор сохраняется в файле config.yaml
- **3.5. Настрока промпта** 
  - Пользователь вводит в поле "Промпт" текст промпта 
  - Пользователь для таблицы с переменными добавляет или удаляет переменные (посоответствующим кнопкам) - при добавлении открывается окно с полями "Имя переменной" (однострочное), "Значение переменной" (многострочное, высота 5 строк)
  - Пользователь вводит в поле "Результат" вносит результат
  - Пользователь может нажимать кнопку "Выполнить промпт", если проходит проверка п.3.6 - система заполняет шаблон промпта переменными - выполняет промпт на LLM as Judge - поле "Результат" заполняется результатом выполнения
- **3.6. Проверка заполнения настроек для выполнения промпта** -
  - система проверяет что:
    - выбраны настройки LLM as Judge, LLM for prompts, для выбранных настроек заданы настройки соответствующей LLM
    - задан текст промпта, для переменных указанных в тексте промпта (по формату "{{Имя переменной}}") - заданы значения всех переменных
  - если настройки не заполнены - действие прерывается
- **3.7. Выполнение промпта в автоматическом режиме**
  - запускается по кнопке "Старт" (кнопка становится недоступной до окончания обработки) с отключенной опцией "Human-in-the-loop"
  - выполняется проверка из п.3.6 - если не прошла - алгоритм не выполняется
  - производится запись в исходные файлы для цикла обработки (prompt.txt, result.txt, {{var}}.txt)
  - выполняется цикл обработки данных (логика в шаблоне в /scripts/template/interview_copilot.py) - при этом происходит логирование шагов и вызова инструментов в поле "Прогресс"
  - после завершения обработки результирующий промпт выводится в поле "Результат оптимизации" (т.е.агент должен возвращать получившийся шаблон промпта)
- **3.7. Выполнение промпта в режиме Human-in-the-loop**
  - запускается по кнопке "Старт" (кнопка становится недоступной до окончания обработки) с включенной опцией "Human-in-the-loop"
  - выполняется проверка из п.3.6 - если не прошла - алгоритм не выполняется
  - производится запись в исходные файлы для цикла обработки (prompt.txt, result.txt, {{var}}.txt)
  - выполняется цикл обработки данных (логика в шаблоне в /scripts/template/interview_copilot.py) - при этом происходит логирование шагов и вызова инструментов в поле "Прогресс" 
    - промежуточный этап с ожиданием промпта 
      - кнопка "Старт" становится активной и меняет текст на "Продолжить" (если поле "Промпт-результат" нажатие приводит к ошибке пользователя)
      - результат из файла srcprompt.txt выводится в поле "Промпт-источник" - его можно скопировать в буфер обмена по кнопке "Копировать"
      - пользователь вводит в поле "Промпт-результат" текст, нажимает кнопку "Продолжить" (конпка становится неактивной)
  - после завершения обработки результирующий промпт выводится в поле "Результат оптимизации" (т.е.агент должен возвращать получившийся шаблон промпта)
